How the quality screens work

Three screens run over every soil-probe reading between download and the published file. This page describes what each one targets and the rule it applies. How much each one removed is measured by running the pipeline twice over 2021–2024, once with the screens and once without, and comparing the two outputs cell by cell.

Order of operations

The screens run in the sequence given on the command line, each handing its result to the next. Nothing here deletes records: screen 1 removes two whole columns, and the other two set individual readings to null, leaving the 20-minute time base intact.

Measurands and screening coverage

Each stationary probe reports five measurands at two lateral positions and three depths — 30 columns. Only two of the five are screened for plausibility; the other three are published exactly as recorded.

Screen 1 — Instrument housekeeping

Non-measurement channels

Columns removed

Battery voltage and radio signal strength describe logger state, not soil state. Both columns are dropped before either value screen sees the record.

Removedbattery_voltage (V) · signal_strength (dBm)

Each named column is dropped in turn. A name that is not present is reported and skipped, so a probe reporting neither channel passes through unchanged rather than failing.

Screen 2 — Bulk conductivity drift

Electrodes lose contact with the soil matrix as it shrinks, cracks or settles, and a poorly coupled electrode reads high. Three rules test each reading against a reference it should agree with: an absolute physical ceiling, its laterally paired probe, and the layer directly above it.

How a record is evaluated

  1. Work through the three depths in turn, 30 cm first.
  2. At each depth, test both probes: a reading is nulled if it exceeds 300 µS/cm outright, or if it sits more than 50 µS/cm above its partner. Only the higher of a disagreeing pair is removed — the lower one is assumed sound.
  3. At 60 and 90 cm only, compare against the layer directly above. If the deeper reading exceeds it by more than 80 µS/cm, the deeper one is nulled.
  4. The depth test is skipped where the reading was already nulled in step 2, so a single bad value is never counted twice.
  5. Nulls are passed over throughout; a missing reading is never treated as a failure.

The depth rule is one-sided. It removes a reading that is implausibly high for its depth, but a reading implausibly low passes untouched.

Screen 3 — Transient water-content spikes NOT IN EFFECT

Soil moisture responds gradually to wetting and drying. A reading that rises abruptly and falls straight back is treated as sensor error; one that rises and persists is treated as a real wetting event. Duration alone separates the two.

This screen does not currently run

The rules below describe intended behaviour. As the code stands they remove nothing: the step rebuilds its per-probe tracker at every reading instead of carrying it forward, so there is never a previous value to compare against and no rise is ever detected. The defect is silent — the step loads, reports no error, and writes no change log. Confirmed by running the step directly against a textbook spike, which it returns unaltered.

How the rule is meant to work

  1. Each probe and depth is tracked separately, walking forward through time and holding the previous reading.
  2. A rise of 5 pp or more over that previous reading opens an excursion, and the reading is marked as provisional.
  3. While an excursion is open every following reading is marked too, however small its own step.
  4. A fall of 5 pp or more closes the excursion and nulls everything marked since it opened.
  5. If instead it stays elevated for 10 readings — a little over three hours — the marks are discarded and the readings kept as a genuine wetting event.
  6. A null reading clears the tracker, so an excursion is never carried across a gap.

Step 1 is where it fails: the tracker is rebuilt from scratch at every reading rather than carried forward, so there is never a previous value and step 2 never fires.

The thresholds are not permissive — they cut into the body of the distribution

Measured on unscreened data, 26.2% of laterally paired readings differ by more than 50 µS/cm and 21.1% of depth steps exceed +80 µS/cm. These are not rare tail events. Only the absolute ceiling behaves like an outlier filter, catching 1.4% of readings.

An earlier version of this page argued the opposite, reading quantiles off the screened output. That reasoning was circular: the screened distribution ends at the threshold because the screen put it there. Nothing about reach can be inferred from it.

Behaviour worth knowing

A screen only runs where its columns exist

Both value screens require the full set of paired-depth columns. Mobile probes report a single surface horizon at 7 cm instead, so the screens find no columns to work on and skip those probes silently — no warning, no change log. The same applies to any probe absent from the sensor mapping, whose columns keep their raw provider names and therefore match nothing.

Thresholds are looser than the software defaults

The ceiling is set to 300 µS/cm against a default of 400, and the depth tolerance to 80 µS/cm against a default of 60 — the ceiling stricter than stock, the depth tolerance looser. The lateral limit of 50 µS/cm is the default, and is the rule that removes the most data. The spike thresholds cannot be configured at all — 5 pp and 10 readings are fixed in the code, and arguments passed to that step are ignored.

Null values carry two meanings

A null is either a screened reading or a reading the probe never returned, and the published file does not distinguish them. Only the per-probe change logs record which values a screen removed.
